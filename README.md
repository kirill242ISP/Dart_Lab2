## Ответы на вопросы

### 1. В чём разница между полем класса и обычной переменной в функции?

**Поле класса** принадлежит объекту (экземпляру класса) и существует столько, сколько существует сам объект. К нему можно обращаться из любого метода этого класса через `this` (или неявно). Каждый объект имеет собственную копию поля.

**Обычная переменная в функции** (локальная переменная) существует только во время выполнения этой функции. Она создаётся при входе в функцию и уничтожается при выходе из неё. Другие функции и объекты к ней доступа не имеют.

**Пример:**

**dart**

```
class Todo {
  String title;        // поле класса — живёт вместе с объектом
  void doSomething() {
    int count = 0;     // локальная переменная — живёт только внутри метода
    count++;
  }
}
```

---

### 2. Что такое конструктор и зачем он нужен?

**Конструктор** — это специальный метод класса, который автоматически вызывается при создании объекта (экземпляра класса). Его основная задача — инициализировать поля объекта начальными значениями.

В Dart конструктор называется так же, как класс. Благодаря null-safety все не-nullable поля должны быть инициализированы, и конструктор — основной способ это сделать.

**Пример:**

**dart**

```
Todo(this.id, this.title) : isDone = false;
```

Здесь при создании `Todo(1, 'Купить продукты')` конструктор принимает `id` и `title`, записывает их в соответствующие поля, а `isDone` устанавливает в `false`.

Без конструктора пришлось бы создавать объект и вручную присваивать каждое поле, что неудобно и чревато ошибками.

---

### 3. Зачем нужен `@override` перед `toString()`? Что будет, если его убрать?

`@override` — это **аннотация**, которая сообщает компилятору, что данный метод переопределяет метод родительского класса. Все классы в Dart неявно наследуются от `Object`, у которого есть метод `toString()`.

**Зачем нужен:**

* Компилятор проверяет, что такой метод действительно существует в родительском классе. Если вы опечатаетесь в имени (например, напишете `toStrring()`), компилятор выдаст ошибку.
* Это улучшает читаемость кода: сразу видно, что метод переопределяет унаследованное поведение.

**Что будет, если убрать:**
Программа продолжит работать — `@override` не является обязательным. Однако вы потеряете проверку компилятора: если случайно опечатаетесь в имени метода, Dart просто создаст новый метод, а не переопределит существующий, и вызов `print(task)` по-прежнему будет выводить `Instance of 'Todo'`. Аннотация помогает избежать таких ошибок.

---

### 4. Чем статическое поле `static int _counter` отличается от обычного поля? Сколько копий этого поля существует в программе?

**Обычное поле** принадлежит каждому объекту отдельно. Если создать 10 объектов `Todo`, у каждого будет своя собственная копия поля `id`, `title` и `isDone`.

**Статическое поле** (`static`) принадлежит **классу целиком**, а не его экземплярам. Оно существует в **единственном экземпляре** на всю программу, независимо от того, сколько объектов класса создано.

**Сколько копий:** В программе существует **ровно одна копия** статического поля `_counter`. Все объекты класса `Todo` используют её совместно.

**Пример:**

**dart**

```
class Todo {
  static int _counter = 0;  // одна на весь класс
  int id;                    // своя у каждого объекта
  Todo({required this.title}) : id = ++_counter;
}
```

При создании первой задачи `_counter` станет `1`, второй — `2` и т.д. Это удобно для автоматической генерации уникальных ID.

---

### 5. Что означает нижнее подчёркивание в `_counter`?

В Dart нижнее подчёркивание `_` в начале идентификатора делает его **приватным для библиотеки** (файла). Это означает, что к полю `_counter` можно обращаться только внутри того же файла (`lib/todo.dart`), где оно объявлено.

Из других файлов (например, из `bin/lab2_todo.dart`) обратиться к `_counter` напрямую нельзя — компилятор выдаст ошибку.

**Важно:** В отличие от Python, где `_` — это лишь соглашение («не трогай, это приватное»), в Dart `_` — это **реальное ограничение на уровне языка**.

**Пример:**

**dart**

```
// lib/todo.dart
class Todo {
  static int _counter = 0;  // приватное для файла todo.dart
}

// bin/lab2_todo.dart
// Todo._counter;  // Ошибка! Приватное поле недоступно из другого файла
```

Это защищает внутреннюю логику класса от случайного вмешательства извне.

## Ответы на вопросы

1. **Что такое абстрактный класс? Почему нельзя написать `Character()` напрямую?**
   Абстрактный класс — это шаблон, который не предназначен для создания экземпляров. Он описывает общий контракт (поля и методы) для наследников. Нельзя создать `Character()`, потому что у него есть абстрактные методы без реализации — Dart не знает, что должен делать `attack()`. Конкретику задают наследники: `Warrior`, `Mage`, `Archer`.
2. **Зачем нужен `super` в конструкторе наследника? Что будет, если его убрать?**
   `super(...)` вызывает конструктор родителя, чтобы инициализировать унаследованные поля (`name`, `hp`, `maxHp`). Если его убрать, компилятор выдаст ошибку: родительский конструктор требует обязательных параметров. Dart не может создать объект наследника, не инициализировав поля родителя.
3. **В чём разница между `@override` у `attack()` в `Warrior` и `takeDamage()` в `Warrior`?**
   `attack()` в родителе — абстрактный (без тела), поэтому `Warrior` обязан его реализовать. `takeDamage()` в родителе уже имеет реализацию, но `Warrior` переопределяет его, чтобы добавить логику брони, и вызывает `super.takeDamage(reduced)` для базового поведения. В обоих случаях `@override` защищает от опечаток: если метода нет в родителе — компилятор сообщит об ошибке.
4. **Функция `fight(Character a, Character b)` не знает, кто реально придёт. Как называется эта концепция и где вы её видели во Flutter?**
   Это **полиморфизм**. Во Flutter любая функция, принимающая `Widget`, работает с `Text`, `Column`, `ElevatedButton` — любым наследником. Например, `build(BuildContext context)` возвращает `Widget`, но реально возвращает конкретного наследника.
5. **Что означает `_random` с нижним подчёркиванием в классе `Character`?**
   Нижнее подчёркивание делает поле **приватным** на уровне библиотеки (файла). К нему нельзя обратиться из другого файла. Это инкапсуляция: детали реализации скрыты, наследники пользуются только публичным API (`attack()`, `takeDamage()` и т.д.).
